评论系统优化与接入指南（Waline × Cloudflare Workers）

花生酱拌饭2025-10-202025-10-20

这是一篇从“问题 → 方案 → 步骤 → 验证 → 常见问题”的完整实战总结。目标是在国内网络环境下，也能稳定、顺滑地使用 Waline 评论系统，同时确保后端能识别到访客的真实 IP。

1. 背景与收益

  • 让前端仅访问 Cloudflare 下的自有域名，规避直连 Vercel 的不稳定/被阻断；
  • 保持原有 Waline 后端（Vercel）不变，前端无感切换；
  • 通过 Worker 补写 X-Forwarded-For / X-Real-IP，让后端记录真实访客 IP；
  • 配合缓存与安全规则，整体体验更稳、更快。

2. 方案总览

  1. 在 Cloudflare Workers 部署一个轻量反代 waline-proxy；
  2. 在 DNS 新建子域（建议 comments.<你的域名>）并开启橙云代理；
  3. 将子域通过 Routes 绑定到 Worker；
  4. 在主题配置中将 Waline 的 serverURL 改为新子域。

  • 发表一条评论，后端显示真实 IP 归属（非 Cloudflare）。

7. 常见问题（FAQ）

  • 仍显示 Cloudflare IP？
    • 确认已部署“写入 X-Forwarded-For / X-Real-IP”的 Worker 版本；
    • 清理浏览器缓存后再发新评论（旧记录不会回溯改 IP）。
  • CORS 报错？将前端域名加入 ALLOW_ORIGINS；保持 HTTPS 与 Full(Strict)。
  • 522/525？上游不可达或证书模式不匹配；检查 UPSTREAM 与 SSL/TLS 设置。
